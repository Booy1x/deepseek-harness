# Agent Note: Markdown 单美元符公式停用，货币金额保持字面

Status: implemented

[English](2026-08-17-markdown-single-dollar-math-currency-conflict.md) | 中文

## Problem

定稿 markdown 语法以默认选项注册了 `micromark-extension-math`，从而启用了单美元符行内公式（`$…$`）。其分词器非常宽松：任意 `$` 开启、下一个 `$` 关闭，空格、换行、中文与任意散文都可作为内容。assistant 回复中成对出现的美元符多为货币金额（`$0.094/M` 与 `$1` 等），因此"闲时输出约 $0.094/M，可以先花 $1 买套餐"这样的句子会被整体吞进一个 `inlineMath` 节点。KaTeX 随后要么把散文渲染成数学斜体乱码，要么沿三段式错误链落到红色 `katex-error` 样式，使受影响的句子看起来像换了字体。

## Decision

`parseGfmWithMath` 改为注册 `math({ singleDollarTextMath: false })`。单独的 `$` 不再是数学分隔符，按字面渲染，货币金额得以保留。TeX 公式仍可通过 `mathCompatibility()` 已提供的分隔符完整使用——`\(…\)`、`\[…\]` 与同一行 `$$…$$` 显示块——以及上游的多美元符文本构造（行内 `$$…$$`，支持 `\tag{}`）。转义的 `\$` 保持上游含义。流式分支（`parseGfm`）本就没有数学，因此两个分支对"单独的美元符是字面文本"达成一致；只有定稿分支的分隔符集合发生了变化。

单元与 DOM 一致性测试现在将货币金额与散文中的美元符作为字面文本覆盖，README（英文与中文）的分隔符清单相应去掉了 `$…$`。

## Alternatives considered

**保留单美元符但要求内容像 TeX。** 否决：内容启发式（花括号配对、不含中文、无空白串）脆弱、对用户不对称地意外，且仍会误判合理的货币字符串；自定义分词器为一项边际能力重复上游语法表面。

**对紧邻数字或 CJK 的美元符做转义。** 否决：按上下文转义会静默改写用户可见的源文本，并制造出第二套只在散文与代码之间区分的美元符方言。

**保持默认并文档化转义手段。** 否决：失败是可见且频繁的——回复中每对货币符号都会被破坏——而文档化的绕行方案（`\$` 或 `\(…\)`）对普通用户不可发现。双美元符门槛（`$$…$$`）保持了真正的公式输入仍然顺手。

## Consequences

货币及任何含 `$` 的散文按字面渲染；原本写成 `$…$` 的公式现在会显示美元符而非公式。公式作者改用 `\(…\)`、`\[…\]` 或 `$$…$$`，定稿语法本就支持这些写法——README 与 `parseGfmWithMath` 的 JSDoc 均已写明。测试固定了散文与表格中的字面美元符、以不配对的 `\(`（而非不配对的 `$`）触发的错误分支，以及 `$$…$$` 行内/显示、数学内部转义美元符、流式延迟与 `math` 围栏等不变行为。
